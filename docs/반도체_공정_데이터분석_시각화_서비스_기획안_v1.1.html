01 개정 방향과 서비스 목적

SEMI GUARD는 SECOM으로 학습한 저장 모델을 사용해 업로드 CSV의 위험 순위를 계산하고, 원본 센서와 예측 결과를 함께 분석하는 서비스다. 이번 개정의 핵심은 위키 중심 조회를 제거하고, Gemini 3.8 Flash가 검증된 Python 분석 Tool을 선택하여 실제 수치에 근거해 답하도록 연결한 것이다.

초기 기획의 데이터 품질 확인, 분석 시작 지원, 검토 우선순위와 근거 제시라는 목적은 유지한다. SECOM은 모델 학습과 시험 평가에 사용하고, 업로드 CSV와 simulation 파일은 추론과 탐색에 사용한다. CSV 등록이 자동 재학습이나 학습 데이터 추가를 뜻하지 않는다.

02 데이터와 구조의 변경

초기 Word 기획은 SECOM 기반 분석 도구를 먼저 완성하는 범위였다. 이후 v2.5에서 확장된 위키와 누적 관제 구성을 현재 코드의 데이터셋별 분석 경로로 정리했다. 다음 비교에서 초기 계획과 중간 구현을 구분한다.

03 화면과 분석 기능의 변경

웹 서비스는 기본 CSV 분석실과 공정 관제 서브페이지로 구성한다. 서브페이지는 기존 배포 화면의 버튼과 상세 페이지를 직접 확인한 뒤 구현했다. 두 화면은 같은 데이터셋 저장소와 추론 파이프라인을 사용한다. 기존 Streamlit과 학습 코드는 보존한다.

AI 확장단일 AI 해설은 선택 기능. 자연어 함수 선택과 DB 이력은 최종 프로젝트 범위.추가. Gemini 3.8 Flash가 실제 Tool을 선택하고 계산 결과로 답함. 후속 질문과 데이터셋별 대화 저장을 구현.

위키 역할의 변화는 세 단계로 구분한다. 초기 기획은 출처가 있는 용어 도움말이며 벡터 DB를 만들지 않는 범위였다. 중간 v2.5 문서는 위키 RAG를 표방했으나, 실제 채팅 코드는 문서 키워드 일치와 고정 응답이었다. 현재 실행 경로는 위키 문서와 관련 API를 제거하고 수치 계산 Tool에 연결한다. 벡터 DB 기반 RAG를 구축하거나 이전한 변경은 아니다.

원안의 센서 의미를 임의로 해석하지 않는 원칙은 유지한다. 중간 확장에서 제시한 설비 원인 단정, 정비 및 인터락 발령은 현재 분석 서비스의 기능과 성과로 사용하지 않는다.

추가된 관제 화면은 엔지니어와 관리자 데모, 월별 및 7일 추이, 전수 표본 필터, 학습 정상군 대비 분포 변화, 수동 점검 등록·보고·승인·보완 이력을 포함한다. 화면 역할 전환은 운영 계정의 권한 검증이 아닌 로컬 업무 흐름 시연이다.

04 데이터 워크플로우

학습과 추론은 저장된 전처리 계약을 공유한다. 사용자 파일을 초기 학습 데이터에 합치지 않는다. 시험 314행을 화면에 불러오는 기능도 저장 모델 추론 경로를 사용하며 별도 학습을 수행하지 않는다.

추론 후 원본 센서와 예측을 row_id로 결합한다. 표본 ID, 파일 해시, 모델 버전과 데이터셋 ID를 보관하므로 정렬과 필터 이후에도 원본을 추적할 수 있다.

학습 정상 1170행은 분포 비교 참고군이다. 사용자가 선택한 기간과 검토 비율은 각 화면의 집계와 표본 범위에 함께 적용한다. 기간별 지표를 전체 파일 지표와 섞어 표시하지 않는다.

로컬 저장은 SQLite다. 서버 세션 쿠키의 소유 범위로 데이터셋·대화·점검을 격리한다. 업로드 시 재학습, 파일 간 자동 누적, 운영 계정 간 공유는 구현 범위에 포함하지 않는다.

05 서비스 워크플로우

CSV 등록 뒤 기본 분석은 Python으로 계산한다. 질문이 들어오면 데이터셋 범위와 함께 Gemini에 전달하고, 에이전트가 필요한 Tool과 인자를 선택한다. 보라색 테두리가 데이터 분석 에이전트 영역이다.

분석실의 질의는 데이터셋에 고정하고, 관제 서브페이지의 질의는 데이터셋·선택 기간·검토 비율 문맥을 구분해 대화를 저장한다. 비율 변경을 직접 요청한 분석은 Tool 인자로 계산할 수 있으며 계산에 사용한 비율을 근거에 표시한다.

데이터 분석 에이전트는 계획, 허용 Tool 실행과 결과 검토 루프를 포함한다. 업로드 검증·모델 추론·기본 EDA·결과 화면·점검 승인은 서비스 계층의 책임이다.

점검 지시는 사람이 통계 결과를 보고 등록한다. 실무자의 항목 확인과 보고 뒤 관리자가 승인 또는 보완 요청한다. 에이전트가 장비를 조작하거나 점검을 자동 발령하지 않는다.

06 분석 도구와 에이전트 계약

분석 주제가 아직 정해지지 않은 상황을 지원하기 위해 기본 분석과 질문 후보를 제공한다. 새로운 질문은 아래 9개 함수의 조합으로 처리한다. 임의 Python 코드, SQL, 쉘을 생성해 실행하는 에이전트는 사용하지 않는다.

기본 분석 6종은 품질, 위험군 차이, 상관, 월별 변화, 정상 참고 분포, 라벨 성능이다. 별도의 LLM 호출 없이 계산한다. 미라벨 데이터에서도 예측과 탐색은 가능하지만 실제 성능은 미확인으로 표시한다.

Gemini 3.8 Flash의 기본 모델 ID는 gemini-3.8-flash다. 서버 환경의 GEMINI_API_KEY 또는 GOOGLE_API_KEY를 사용하고 GEMINI_MODEL로 변경할 수 있다. 키를 프런트엔드에 넣지 않는다.

최대 6회 응답 루프와 12회 Tool 호출로 제한하고 조회 결과는 50행과 선택 20열까지 반환한다. 계산 성공 근거 없이 최종 답변을 성공으로 처리하지 않는다. 질문과 필요한 계산 요약은 Google Gemini에 전송한다.
